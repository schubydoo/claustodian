    Use it from your own code

    Static JSON at stable URLs — no API, no key, no install. A version snapshot lists only the symbols available at that version, so presence is the answer. 

    # Does --safe-mode exist in 2.1.169?  (exit 0 = yes)
curl -fsSL https://claustodian.dev/data/versions/2.1.169.json \
  | jq -e '.symbols[] | select(.symbol == "--safe-mode")' >/dev/null \
  && echo available || echo "not available"
    # stdlib only
import json, urllib.request

url = "https://claustodian.dev/data/versions/2.1.169.json"
with urllib.request.urlopen(url) as r:
    snap = json.load(r)

print(any(s["symbol"] == "--safe-mode" for s in snap["symbols"]))
    // zero dependencies, Node 18+
const url = 'https://claustodian.dev/data/versions/2.1.169.json';
const snap = await fetch(url).then((r) => r.json());

console.log(snap.symbols.some((s) => s.symbol === '--safe-mode'));

    Fuller clients, all runnable and dependency-light: quickstart.sh, claustodian.py, claustodian.ts. Building on top of this with an agent? Point it at llms.txt.

    sinceX is the earliest version Claustodian observed a symbol; it's available in any version Y where first_seen ≤ Y and it hasn't been removed. A dashed since≤X chip marks an estimated first_seen — an upper bound from an incidental mention or a doc with no stated introduction version, so the true version may be earlier (the binary lane will pin it). Solid chips are confirmed. Descriptions come from Anthropic's official docs where available.

    A under remote-control chip means the flag is only accepted under that invocation — claude --sandbox fails where claude remote-control --sandbox works. Scopes are full paths, so under plugin eval means exactly that: claude plugin --scaffold fails too, because the flag belongs to plugin eval and not to plugin. The list is complete, so a flag without the chip simply has no scope information recorded; it does not mean the flag is top-level.

    Config keys carry a category chip. settings and settings-internal both live in settings.json, the latter marked @internal by Anthropic. global-config is a different file: those keys belong in ~/.claude.json and are silently ignored if you put them in settings.json.

    A flag with category cli-internal is hidden from claude --help. It is real and the CLI accepts it, but something else sets it — a spawning parent process, the teammate orchestrator, a deep link — so passing it yourself usually does nothing useful. cli flags are the ones meant for you.

    An unreviewed badge means the symbol was found in an official release binary but has not been human-curated yet. It exists — that is what the binary proves — but its description may be terse or missing. Treat it as real, not as "maybe."
